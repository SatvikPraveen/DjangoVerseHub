# API Reference

Base URL: `/api/v1/` (relative to wherever the site runs, e.g. `http://localhost:8000/api/v1/`).
Interactive docs generated by drf-spectacular: Swagger UI at `/api/v1/docs/`, ReDoc at `/api/v1/redoc/`, OpenAPI 3 JSON/YAML at `/api/v1/schema/`. The schema is the complete, always-current reference; this page explains the conventions and lists each resource with its notable actions.

Router-mounted resources (`users`, `profiles`, `articles`, `categories`, `tags`, `comments`, `notifications`) accept an optional trailing slash and a `.json` format suffix. They are also reachable under the app prefixes `/users/api/`, `/articles/api/` and `/comments/api/` (same viewsets, different URL names); prefer `/api/v1/`.

## Authentication

Default authentication classes (`REST_FRAMEWORK["DEFAULT_AUTHENTICATION_CLASSES"]`): JWT, DRF token, session, in that order. Default permission is `IsAuthenticated`; individual views relax it as noted below.

### DRF token

```http
POST /api/v1/auth/token/
Content-Type: application/json

{"username": "you@example.com", "password": "secret"}
```

`rest_framework.authtoken`'s view expects the field name `username`; because the user model logs in by email, pass the email address there. Response: `{"token": "<40-char key>"}`.

```http
POST /api/v1/auth/login/
{"email": "you@example.com", "password": "secret"}
```

Project login view (throttle scope `login`, 10/minute per IP). Response: `{"token": "...", "user": {"id", "email", "username", "full_name", "is_verified", "is_staff"}}`. `POST /api/v1/auth/logout/` (authenticated) deletes the caller's token and returns 204.

Send the token as `Authorization: Token <key>`.

### JWT (djangorestframework-simplejwt)

| Endpoint | Body | Response |
| --- | --- | --- |
| `POST /api/v1/auth/jwt/create/` | `{"email", "password"}` | `{"access", "refresh"}` |
| `POST /api/v1/auth/jwt/refresh/` | `{"refresh"}` | new `access` and, because rotation is on, a new `refresh`; the old refresh token is blacklisted |
| `POST /api/v1/auth/jwt/verify/` | `{"token"}` | 200 if valid, 401 otherwise |
| `POST /api/v1/auth/jwt/blacklist/` | `{"refresh"}` | revokes a refresh token |

Lifetimes: access 30 minutes, refresh 14 days (`JWT_ACCESS_MINUTES`, `JWT_REFRESH_DAYS`). Header: `Authorization: Bearer <access>`. `last_login` is updated on token creation.

All three schemes work on every endpoint, including the resource viewsets.

### Session

Browser clients that logged in through the website are authenticated by the session cookie. Unsafe methods must send the CSRF token in the `X-CSRFToken` header (`CSRF_COOKIE_HTTPONLY` is `False` so JavaScript can read the `csrftoken` cookie).

## Error envelope

`apps/api/exceptions.py` wraps every error response produced by DRF:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Invalid input.",
    "details": {"content": ["Content must be at least 100 characters long."]},
    "request_id": "7f4c0d0e9a3b4b7c9c1d2e3f4a5b6c7d"
  }
}
```

| HTTP | `code` | Notes |
| --- | --- | --- |
| 400 | `validation_error` | `details` holds the serializer errors keyed by field (or `non_field_errors`) |
| 401 | `not_authenticated`, `authentication_failed`, `token_not_valid` | DRF/simplejwt default codes |
| 403 | `permission_denied` | |
| 404 | `not_found` | |
| 405 | `method_not_allowed` | |
| 409 | `conflict` | raised for database `IntegrityError` |
| 429 | `throttled` | `Retry-After` header is set by DRF |

`details` is omitted when there is nothing beyond the message. `request_id` equals the `X-Request-ID` response header (and the id in server logs); send your own `X-Request-ID` to have it echoed. Responses from the `RateLimitMiddleware` (HTTP 429, plain text `Rate limit exceeded`) are produced before DRF and are not enveloped.

## Pagination, filtering, ordering

- Default pagination: `PageNumberPagination`, 20 per page, `?page=N`. Response shape: `{"count", "next", "previous", "results"}`.
- `comments` and `notifications` use their own paginator: same shape plus `?page_size=` (max 100); notifications add `"unread_count"`.
- List actions on `articles` (`featured`, `popular`, `trending`) return plain arrays limited to 10 items; `categories/{id}/articles/` and `tags/{id}/articles/` return unpaginated arrays.
- Filtering: `django-filter` on the fields listed per resource (`?field=value`). Full-text style search: `?search=term` on the `search_fields`. Ordering: `?ordering=field` or `?ordering=-field` on the `ordering_fields`.

## Throttling

`REST_FRAMEWORK["DEFAULT_THROTTLE_RATES"]`:

| Scope | Rate | Applied to |
| --- | --- | --- |
| `anon` | 100/hour | every API view for unauthenticated clients (`AnonRateThrottle`) |
| `user` | 1000/hour | every API view for authenticated users (`UserRateThrottle`) |
| `login` | 10/minute | `POST /auth/login/` (keyed by IP) |
| `search` | 60/minute | `GET /search/` |
| `comments` | 30/hour | `POST /comments/` (per user) |
| `registration` | 5/hour | defined; no view currently uses `RegistrationRateThrottle` |

The global throttles are disabled under the test settings; scoped throttles keep their rates. Independently of DRF, `RateLimitMiddleware` limits every non-admin request to `RATE_LIMIT_REQUESTS_PER_MINUTE` (100) per client IP per minute when `RATE_LIMIT_ENABLED` is true and `DEBUG` is false.

## Users

`UserViewSet` (`apps/users/views.py`): list, retrieve, update (`PUT`/`PATCH`); no create (use `register`) and no delete on `/users/{uuid}/` (delete your own account through `DELETE /users/me/`). Only users with public profiles are listed (plus yourself). Auth: Token or session; `register` and `login` are public.

| Method | Path | Description |
| --- | --- | --- |
| GET | `/users/` | list (`UserListSerializer`: `id`, `username`, `display_name`, `avatar_url`, `date_joined`, `is_active`) |
| GET | `/users/{uuid}/` | detail (`UserSerializer`); private fields (`phone_number`, `date_of_birth`, `login_count`, `last_login`, `email_verified`, and `email` unless the profile allows it) are only returned to the owner or staff; includes `followers_count`, `following_count`, `is_following`, nested `profile` |
| PUT/PATCH | `/users/{uuid}/` | own record only: `first_name`, `last_name`, `phone_number`, `date_of_birth` |
| GET/PATCH/DELETE | `/users/me/` | current user; PATCH takes the same fields as above; DELETE with `{"password": "<current password>"}` removes the account and returns `{"detail": "Account removed.", "outcome": "deleted" or "anonymised"}` (accounts with published articles are anonymised so their articles stay readable) |
| GET/POST | `/users/me/export/` | the caller's data (account, profile, articles, comments, likes, bookmarks, follows, notifications) as a JSON attachment |
| POST | `/users/register/` | `{"email", "username", "password", "password_confirm", "first_name"?, "last_name"?}` → 201 `{"user", "token"}`; a verification email is queued after commit |
| POST | `/users/login/` | `{"username": "<email or username>", "password", "remember_me"?}` → `{"user", "token"}` |
| POST | `/users/logout/` | revokes the DRF token |
| POST | `/users/change-password/` | `{"current_password", "new_password", "new_password_confirm"}` |
| POST | `/users/{uuid}/follow/` | follow; 201 when created, 200 if already following; `{"is_following", "created", "followers_count"}`; 400 for self |
| POST/DELETE | `/users/{uuid}/unfollow/` | `{"is_following": false, "removed", "followers_count"}` |
| GET | `/users/{uuid}/followers/` | paginated users following this user |
| GET | `/users/{uuid}/following/` | paginated users this user follows |

Following a user creates a `follow` notification for the target (see Notifications).

## Profiles

`ProfileViewSet`: list, retrieve, update. Public profiles are visible to everyone (`list`, `retrieve`, `search` allow anonymous access); a profile can only be modified by its owner. `{pk}` is the profile id, or the literal `me` for the caller's own profile.

| Method | Path | Description |
| --- | --- | --- |
| GET | `/profiles/` | public profiles (`ProfileSerializer`; preference fields such as `theme`, `timezone`, `email_notifications` are stripped unless you are the owner/staff; `email`/`full_name` follow the `show_email`/`show_real_name` flags) |
| GET | `/profiles/{id}/` (or `/profiles/me/`) | one profile |
| PUT/PATCH | `/profiles/{id}/` (or `/profiles/me/`) | own profile: `full_name`, `bio`, `avatar` (image, ≤5 MB), `cover_image` (≤10 MB), `gender`, `location`, `website`, social links, `theme`, `timezone`, `language`, privacy and notification switches |
| GET | `/profiles/search/?q=` | up to 20 public profiles matching username/full name/bio (`PublicProfileSerializer`) |
| GET | `/profiles/{id}/stats/` (or `/profiles/me/stats/`) | `{"activity_stats", "profile_completion"}` (own or public profiles only) |

## Articles

`ArticleViewSet`: full CRUD. Reads are public; writes require Token/session auth; updates and deletes are restricted to the author (`IsOwnerOrReadOnly`). The queryset applies the visibility rules: published articles for everyone, plus your own drafts/archived articles; staff see everything.

Filters: `?status=`, `?category=<id>`, `?tags=<id>`, `?is_featured=`; `?search=` over `title`, `content`, `summary`; `?ordering=` over `created_at`, `published_at`, `views_count`, `likes_count` (default `-created_at`).

| Method | Path | Description |
| --- | --- | --- |
| GET | `/articles/` | paginated `ArticleListSerializer` (author, category, tags, `featured_image_url`, counters, `reading_time`, `liked`, `bookmarked`, ...) |
| POST | `/articles/` | `{"title" (≥5 chars), "content" (≥100 chars), "summary"?, "category"?, "tags": [ids], "featured_image"?, "status", "allow_comments", "meta_description", "meta_keywords"}`; `is_featured` is honoured for staff only; `slug` and `author` are set server-side |
| GET | `/articles/{uuid}/` | `ArticleDetailSerializer` including `content`, SEO fields and three `related_articles` |
| PUT/PATCH | `/articles/{uuid}/` | author only; a change to title/content/summary records an `ArticleRevision` with the caller as editor |
| DELETE | `/articles/{uuid}/` | author only |
| POST | `/articles/{uuid}/like/` | toggle like → `{"liked", "likes_count"}`; 400 unless published |
| POST | `/articles/{uuid}/bookmark/` | toggle bookmark → `{"bookmarked"}`; 400 unless published |
| GET | `/articles/{uuid}/revisions/` | revision snapshots (`title`, `summary`, `content`, `editor`, `created_at`); author or staff only (403 otherwise) |
| POST | `/articles/{uuid}/increment_views/` | public; counts one view per session/IP per hour → `{"views_count"}` |
| GET | `/articles/featured/` | up to 10 featured published articles |
| GET | `/articles/popular/` | up to 10 by views + likes (`PopularArticleSerializer`) |
| GET | `/articles/trending/` | up to 10 from the last 7 days by views + 2 × likes |
| GET | `/articles/bookmarked/` | authenticated; paginated articles the caller bookmarked, newest bookmark first |

Liking an article notifies its author; publishing an article notifies the author's followers.

## Categories and tags

`CategoryViewSet` and `TagViewSet`: reads are public, writes require staff (`IsStaffOrReadOnly`). Both expose `article_count` (published articles). Categories: `?search=` over name/description. Tags: `?search=` over name.

| Method | Path | Description |
| --- | --- | --- |
| GET/POST | `/categories/` | active categories; create: `{"name", "description", "image", "is_active"}` (`slug` generated) |
| GET/PUT/PATCH/DELETE | `/categories/{id}/` | |
| GET | `/categories/{id}/articles/` | published articles in the category (array) |
| GET/POST | `/tags/` | create: `{"name"}` (lower-cased, unique) |
| GET/PUT/PATCH/DELETE | `/tags/{id}/` | |
| GET | `/tags/popular/` | 20 tags with the most published articles |
| GET | `/tags/{id}/articles/` | published articles with the tag (array) |

## Comments

`CommentViewSet`: comments are generic; a comment belongs to a `content_type` + `object_id` pair. Reads are public (non-staff only see active comments); creating requires authentication (throttle `comments`, 30/hour); editing is allowed for the author within 15 minutes of posting or for staff; deleting (a soft delete) for the author or staff. Max thread depth is 3 (root = depth 0).

Filters: `?content_type=<ContentType id>&object_id=<uuid>` to scope to one object, `?parent=<uuid>` for direct replies; `?search=` over content and author names; `?ordering=created_at|likes_count` (default `created_at`).

| Method | Path | Description |
| --- | --- | --- |
| GET | `/comments/` | paginated (`page_size` up to 100) `CommentSerializer`: `author`, `content`, `parent`, `is_edited`, `likes_count`, `reply_count`, `total_replies`, `thread_depth`, `can_edit`, `can_delete`, `liked`, `content_object_name`; `is_flagged` only for staff |
| POST | `/comments/` | `{"content" (3–1000 chars), "content_type": "articles.article", "object_id": "<uuid>", "parent"?: "<uuid>"}`; the target must accept comments (published, `allow_comments`) and the parent must be on the same object and shallower than the depth limit |
| GET | `/comments/{uuid}/` | |
| PUT/PATCH | `/comments/{uuid}/` | `{"content"}`; marks the comment edited |
| DELETE | `/comments/{uuid}/` | soft delete (content replaced, `is_active=false`) |
| POST | `/comments/{uuid}/like/` | toggle → `{"liked", "likes_count"}` |
| POST | `/comments/{uuid}/flag/` | `{"reason": one of spam, offensive, harassment, off_topic, copyright, other; "details"?}`; one flag per user; the comment becomes flagged after 3 distinct reporters (immediately for staff); 400 for your own comment or a repeat flag |
| GET | `/comments/{uuid}/stats/` | `likes_count`, `reply_count`, `total_replies`, `thread_depth`, `flag_count` (staff only, else null) |
| GET | `/comments/tree/?content_type=app_label.model&object_id=<uuid>` | nested thread (`CommentTreeSerializer` with `replies`); hidden comments that still have replies appear as `[removed]` placeholders. Note the `app_label.model` form here versus the numeric ContentType id used by the list filter |
| GET | `/comments/user_comments/` | authenticated; the caller's comments, newest first |

Creating a comment notifies the article author (or the parent comment's author for replies) and emails them if their preferences allow; every new comment is checked by the auto-moderation task.

## Notifications

`NotificationViewSet` (authenticated only) exposes the caller's own notifications. Notifications are created by the system, so `POST /notifications/` returns 405. Filters: `?status=unread|read` (or `?unread=true`), `?type=like|comment|follow|mention|post|system`. Pagination adds `unread_count`.

| Method | Path | Description |
| --- | --- | --- |
| GET | `/notifications/` | `NotificationSerializer`: `id`, `notification_type`, `message`, `sender` (with `display_name`, `avatar_url`), `is_read`, `created_at`, `read_at`, `time_since`, `url`, `icon`, `color`, `content_object_data` |
| GET | `/notifications/{id}/` | |
| PATCH | `/notifications/{id}/` | only `{"is_read": <bool>}` |
| DELETE | `/notifications/{id}/` | |
| POST | `/notifications/{id}/mark_read/` | `{"status": "success"}` |
| POST | `/notifications/mark_all_read/` | `{"status": "success", "marked_count"}` |
| GET | `/notifications/unread_count/` | `{"unread_count"}` |
| GET/PUT/PATCH | `/notifications/preferences/` | `NotificationPreferenceSerializer`: `in_app_like`, `in_app_comment`, `in_app_follow`, `in_app_mention`, `in_app_post`, `email_like`, `email_comment`, `email_follow`, `email_mention`, `email_post`, `digest_frequency` (`none` = immediate email, `daily`, `weekly`), `updated_at` |

The website's JavaScript uses an equivalent set of function views under `/notifications/api/` (`GET /notifications/api/`, `POST /notifications/api/{id}/read/`, `DELETE|POST /notifications/api/{id}/delete/`, `POST /notifications/api/read-all/`, `GET /notifications/api/unread-count/`, `GET|PUT|PATCH /notifications/api/preferences/`). They use the default DRF authentication classes and return the same payloads.

Real-time delivery over `/ws/notifications/` is described in the README.
